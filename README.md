# Ballast-free catamaran: stability app

Arova Engineering Challenge 2026, combined path (mechanical + ICT + integration).

One app to load a model catamaran, assess it, compare two hull versions and
check the model against tank tests. No ballast water: stability comes from the
hull spacing and the cargo placement.

## Setup

Requirements: Node.js 20.19+ or 22.12+ (needed by Vite 8), a recent Chrome or
Edge (Web Serial and Web Bluetooth are only used for live sensor mode).

```bash
npm install
npm run dev        # development server
npm run build      # production build into dist/
npm run preview    # serve dist/ locally (do not open dist/index.html directly)
```

Required files that are not generated by npm (keep them in `public/`):

- `public/models/boat.glb`: 3D model of the printed catamaran (display only).
- `public/textures/waternormals.jpg`: water normal map for the 3D ocean.

Internet is needed for the OpenStreetMap tiles on the Routes tab (routes are
still drawn on a blank background without it) and for `puck.js`, which is only
used for the Bangle.js connection.

## What it does

- **Stability tab:** draft, freeboard, GM, heel, roll, trim, pitch, heave and
  drag. Version A against version B under the same cargo, water and waves.
  Cargo limit and load margin. Hull spacing sweep (GM and roll period).
- **Cargo editor:** drag boxes in 3D or type mass and position. Overlap and
  deck-edge checks. "Suggest layout" searches for a valid layout with the
  centre of gravity as close to the centreline as possible. Box dimensions are
  stored in `src/data/data.js`; the table edits mass, x and y only.
- **Validation tab:** calculated against measured values with the difference
  in percent. Load tests from CSV, MPU-6050 recordings from CSV.
- **Dashboard tab:** live roll and pitch, simulated from the model or measured
  from an MPU-6050 (USB serial) or a Bangle.js watch (Bluetooth). Alerts
  against the limits and suggested corrections. Save the shown data as CSV.
- **Routes tab:** five routes from Turku (Helsinki, Stockholm, Gdańsk,
  Copenhagen, Gothenburg) coloured by estimated water density. Draft,
  freeboard, load margin and a GO / CAUTION / NO-GO decision for the current
  load, plus the shortest route that keeps the freeboard limit.

All results are labelled calculated, simulated, estimated or measured.
Units: kg, m, s, N, kg/m³ and degrees (the UI shows g and mm for readability).

## Methods

- Buoyancy: `V = M / rho`. Draft from the hull table (submerged volume against
  draft, exported from CAD, linear interpolation).
- Centre of gravity: `xCG = sum(m*x) / sum(m)`, same for y and z.
- Stability: `GM = KB + BM - KG`. BM is corrected for the hull spacing with the
  parallel axis theorem: `BM = BM_table + Awp * ((s/2)^2 - (s_CAD/2)^2) / V`.
- Heel: `heel = atan(yCG / GM)`. Trim: `trim = atan((xCG - LCB) / GML)`.
- Roll and pitch: one degree of freedom, resonance response to the wave slope
  `atan(pi * Hw / wavelength)`, deep-water wavelength `g * Tw^2 / (2 * pi)`.
- Heave: natural period from the waterplane area, added mass equal to the mass.
- Drag: `F = 0.5 * rho * Cd * A * v^2` with `A = 2 * b * draft` (two hulls,
  frontal area).
- Cargo limit: the mass at which freeboard drops to 30 mm. Load margin is that
  limit minus the current cargo.
- Water density from salinity: `rho = 999.8 + 0.78 * S` (about 10 °C).
- Measured GM estimate from a recording: `GM_meas = GM_calc * (T_calc / T_meas)^2`.

## Assumptions and limits

- Roll inertia radius `0.4 * (spacing + hull width)`, pitch inertia radius
  `0.25 * length`. Damping ratio 0.1 (roll and pitch), 0.3 (heave).
- `Cd = 0.8` is a conservative placeholder for a blunt body, not a measured
  value. Drag is an estimate.
- The hull table comes from the base CAD model. Changing the spacing changes
  the calculation only. The 3D view always shows the base model.
- Limits used for alerts: heel 5°, roll 10°, pitch 10°, trim 3°, freeboard
  30 mm, test cargo 150 to 400 g.
- Because the hulls are far apart, GM is large and heel is small for a
  symmetric load. The model carries much more than the 400 g test range before
  the 30 mm freeboard limit is reached.
- Route salinity values are typical surface values, rounded. Waypoints are
  schematic and not for navigation. Draft changes between routes are small
  (fractions of a millimetre) for test-range cargo.
- The waves in the 3D view illustrate the calculation. They are not a fluid
  simulation. No CFD was run in this app.

## Data files

- `src/data/hullData.json`: hydrostatic table and dimensions from CAD.
- `src/data/data.js`: hull versions A and B, default cargo.
- Tests CSV: `version,freeboard_mm,heel_deg,period_s,note`
- Sensor CSV: `t_ms,roll_deg,pitch_deg`
- Serial lines for live mode (USB, 115200 baud): six raw integers per line,
  `ax,ay,az,gx,gy,gz` (MPU-6050 raw register values).
- Bangle.js mode: the app uploads a short script that streams `x,y,z`
  accelerometer values in milli-g. Accelerometer only, no gyro.

## Project structure

- `src/App.jsx`: layout, version comparison, validation, export.
- `src/data/physics.js`: the calculation (`assess`). `hydro.js`: hull table
  lookup. `routes.js`: routes and density. `motion.js`: sensor CSV analysis.
- `src/useSensor.js`: serial and Bluetooth input, filter.
- `src/Scene.jsx`, `src/Ocean.jsx`: 3D view. `src/Dashboard.jsx`,
  `src/RoutePlanner.jsx`: tabs. `src/utils.js`: placement checks and layout
  search.
